# Jobs Persistence Implementation Plan (Plan 3B)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the `Jobs` module behind PostgreSQL — EF Core mapping, migrations, the repository, the schema and its indexes — and prove every part of it against a real database rather than a mock.

**Architecture:** `Jobs.Infrastructure` implements the interfaces `Jobs.Domain` declares and is the only project that names EF Core. Tenant isolation is enforced by a global query filter below the query, so a query written with no tenant condition still cannot return another organization's rows. The repository is split with `partial` by responsibility, and its read side returns a projection rather than aggregates (D-25).

**Tech Stack:** EF Core 9, Npgsql, EFCore.NamingConventions, Testcontainers.PostgreSql, PostgreSQL 17.11.

**Spec:** `context/design.md` B7 (the DDL, the indexes, the search query); `context/architecture.md` 6.1-6.4 (schema per module, mapping rules, indexing, cursor pagination), 7.2 (multi-tenancy), 8.2 (the integration suite)

**Split:** This is plan 3B, the data half. Plan 3C adds `Jobs.Presentation`, `Common.Presentation` with `ProblemDetails`, `JobTracker.Api` as the composition root, and `HttpJobsAdapter` on the frontend — the seam is where HTTP enters.

**Rubric reach:** Repository + UoW (5) and all of section 4 — Schema design (4) and Indexing + optimization (3). Clean Architecture layers (3) completes in 3C, when the fourth layer exists.

## Global Constraints

- **No public setters on an aggregate**; `Domain` references only `Common.Domain`; `Application` never references `Infrastructure`. The architecture tests from 3A already enforce all three and must stay green
- **Read queries use projections and no change tracking** (architecture 9.2), and that binds `SearchAsync` (D-25)
- **Test-driven.** Infrastructure is production code, so it is written against a failing integration test (D-27, D-28). Migrations are generated by `dotnet ef`, which is the generated-code exemption of architecture 8.3 — but the migration is verified by a test that applies it
- **Every integration test runs against a real PostgreSQL** started by Testcontainers. No in-memory provider: it does not enforce a check constraint, does not have a query planner, and would pass every test this suite exists to fail
- **Assert behaviour, never a query plan.** A plan depends on table statistics, so asserting one fails on a small fixture for reasons that are not defects. Plans go in `database/queries.sql` as captured `EXPLAIN (ANALYZE, BUFFERS)` output
- Warnings are errors. `dotnet build` and `dotnet test` both green before any commit
- **After a deliberate red, run `dotnet clean`.** Plan 3A lost time to a stale artefact: `sed` restored the source, MSBuild did not rebuild, and the rule kept reading the old DLL

```csharp
using JobTracker.Common.Infrastructure;
using JobTracker.Modules.Jobs.Infrastructure;
using Microsoft.EntityFrameworkCore;

namespace JobTracker.IntegrationTests;

[Collection(PostgresCollection.Name)]
public abstract class IntegrationTestBase(PostgresFixture postgres) : IAsyncLifetime
{
    protected static readonly Guid Organization = Guid.Parse("11111111-1111-1111-1111-111111111111");
    protected static readonly Guid OtherOrganization = Guid.Parse("22222222-2222-2222-2222-222222222222");

    protected JobsDbContext Context { get; private set; } = null!;

    /// <summary>
    /// Builds a context for a different organization against the same data.
    /// Tenant isolation cannot be tested with one context: the filter has to be
    /// shown *not* returning rows a second tenant should not see.
    /// </summary>
    protected JobsDbContext ContextFor(Guid organizationId) =>
        new(BuildOptions(), new FixedTenantContext(organizationId));

    private DbContextOptions<JobsDbContext> BuildOptions() =>
        new DbContextOptionsBuilder<JobsDbContext>()
            .UseNpgsql(postgres.ConnectionString)
            .UseSnakeCaseNamingConvention()
            .Options;

    public async Task InitializeAsync()
    {
        Context = new JobsDbContext(BuildOptions(), new FixedTenantContext(Organization));

        // A clean schema per test rather than a clean container: same
        // isolation, a hundredth of the cost. Dropping and re-migrating also
        // means every test exercises the migration, which is case 1 of
        // architecture 8.2 running continuously rather than once.
        await Context.Database.EnsureDeletedAsync();
        await Context.Database.MigrateAsync();
    }

    public async Task DisposeAsync() => await Context.DisposeAsync();
}
```

```csharp
using JobTracker.Common.Domain;
using JobTracker.Common.Infrastructure;
using JobTracker.Modules.Jobs.Domain;
using Microsoft.EntityFrameworkCore;

namespace JobTracker.Modules.Jobs.Infrastructure;

public sealed class JobsDbContext(
    DbContextOptions<JobsDbContext> options,
    ITenantContext tenant) : DbContext(options)
{
    public const string Schema = "jobs";

    public DbSet<Job> Jobs => Set<Job>();
    public DbSet<Assignee> Assignees => Set<Assignee>();
    public DbSet<Customer> Customers => Set<Customer>();

    internal Guid OrganizationId => tenant.OrganizationId;

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // One schema per module. A module's DbContext maps only its own tables,
        // so a query that reaches across modules fails to compile rather than
        // quietly joining (architecture 6.1).
        modelBuilder.HasDefaultSchema(Schema);
        modelBuilder.ApplyConfigurationsFromAssembly(typeof(JobsDbContext).Assembly);
    }
}
```

- [ ] **Step 4: Write `JobConfiguration.cs`**

```csharp
using JobTracker.Modules.Jobs.Domain;
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;

namespace JobTracker.Modules.Jobs.Infrastructure.Configurations;

internal sealed class JobConfiguration : IEntityTypeConfiguration<Job>
{
    public void Configure(EntityTypeBuilder<Job> builder)
    {
        builder.ToTable("jobs");
        builder.HasKey(job => job.Id);

        builder.Property(job => job.Title).IsRequired().HasMaxLength(200);
        builder.Property(job => job.Description);

        // Text with a CHECK, not an ordinal: readable in a psql session,
        // diff-friendly in migrations, and safe against the ordinal drift that
        // makes integer-backed enums dangerous across deployments.
        builder.Property(job => job.Status)
            .HasConversion<string>()
            .IsRequired()
            .HasMaxLength(20);

        builder.Property(job => job.OrganizationId).IsRequired();
        builder.Property(job => job.CustomerId).IsRequired();

        // No identity, so no table. Flattened onto the job row.
        builder.OwnsOne(job => job.Address, address =>
        {
            address.Property(a => a.Street).HasColumnName("street").IsRequired();
            address.Property(a => a.City).HasColumnName("city").IsRequired();
            address.Property(a => a.State).HasColumnName("state").IsRequired();
            address.Property(a => a.ZipCode).HasColumnName("zip_code").IsRequired();
            address.Property(a => a.Latitude).HasColumnName("latitude")
                .HasPrecision(9, 6).IsRequired();
            address.Property(a => a.Longitude).HasColumnName("longitude")
                .HasPrecision(9, 6).IsRequired();
        });
        builder.Navigation(job => job.Address).IsRequired();

        builder.HasMany(job => job.Photos)
            .WithOne()
            .HasForeignKey(photo => photo.JobId)
            .OnDelete(DeleteBehavior.Cascade);

        builder.Metadata
            .FindNavigation(nameof(Job.Photos))!
            .SetPropertyAccessMode(PropertyAccessMode.Field);

        builder.Property<DateTimeOffset>("CreatedAt")
            .HasDefaultValueSql("now()")
            .ValueGeneratedOnAdd();

        builder.Property<DateTimeOffset>("UpdatedAt")
            .HasDefaultValueSql("now()");

        builder.HasCheckConstraint(
            "ck_jobs_completed_has_signature",
            "status <> 'Completed' OR signature_url IS NOT NULL");

        builder.HasCheckConstraint(
            "ck_jobs_cancelled_has_reason",
            "status <> 'Cancelled' OR cancellation_reason IS NOT NULL");

        // NFR-1. The filter sits below the query, so a query written with no
        // tenant condition still cannot return another organization's rows.
        // Layers 1, 3 and 4 of architecture 7.2 exist so a mistake here is
        // caught rather than exploited; this is layer 2, the one doing the work.
        builder.HasQueryFilter(job =>
            job.OrganizationId == EF.Property<Guid>(job, nameof(Job.OrganizationId))
            && job.OrganizationId == OrganizationIdOf(builder));
    }

    // Placeholder: the filter needs the runtime tenant, which a static
    // configuration cannot reach. Step 5 replaces this with the working form.
    private static Guid OrganizationIdOf(EntityTypeBuilder<Job> _) => Guid.Empty;
}
```

- [ ] **Step 5: Fix the query filter, which cannot be static**

The form above does not work: a query filter is built once per model and needs the *current* tenant. EF's answer is to close over the context. Replace the filter with a context-side declaration in `JobsDbContext.OnModelCreating`, after `ApplyConfigurationsFromAssembly`:

```csharp
        // The filter closes over `this`, so it reads the tenant of the context
        // the query runs on. Declared here rather than in the configuration
        // because IEntityTypeConfiguration is static and has no context to
        // close over.
        modelBuilder.Entity<Job>().HasQueryFilter(job => job.OrganizationId == OrganizationId);
        modelBuilder.Entity<Assignee>().HasQueryFilter(a => a.OrganizationId == OrganizationId);
        modelBuilder.Entity<Customer>().HasQueryFilter(c => c.OrganizationId == OrganizationId);
```

and delete the `HasQueryFilter` and the placeholder from `JobConfiguration`.

```csharp
using FluentAssertions;
using JobTracker.Common.Domain;

namespace JobTracker.ArchitectureTests;

public sealed class TenantRules
{
    [Fact]
    public void Every_tenant_scoped_entity_has_a_query_filter()
    {
        using var context = TestContext();

        var scoped = Types.InAssembly(typeof(Modules.Jobs.Domain.Job).Assembly)
            .That().ImplementInterface(typeof(ITenantScoped))
            .GetTypes()
            .ToList();

        var unfiltered = scoped
            .Select(type => context.Model.FindEntityType(type))
            .Where(entity => entity is not null && entity.GetQueryFilter() is null)
            .Select(entity => entity!.ClrType.Name)
            .ToList();

        // Layer 4 of architecture 7.2: adding a tenant-scoped table cannot
        // silently omit the protection, because this fails when it does.
        unfiltered.Should().BeEmpty();
    }
```

```csharp
using JobTracker.Modules.Jobs.Domain;
using Microsoft.EntityFrameworkCore;

namespace JobTracker.Modules.Jobs.Infrastructure.Repositories;

internal sealed partial class JobRepository
{
    /// <summary>
    /// Tracked on purpose: this loads an aggregate a command is about to
    /// change, and the change tracker is how the unit of work knows what to
    /// write. The read side below is the untracked one.
    /// </summary>
    public Task<Job?> GetByIdAsync(Guid id, CancellationToken cancellationToken = default) =>
        context.Jobs
            .Include(job => job.Photos)
            .SingleOrDefaultAsync(job => job.Id == id, cancellationToken);

    public async Task<IReadOnlyList<JobSearchResult>> SearchAsync(
        JobSearchCriteria criteria, CancellationToken cancellationToken = default)
    {
        var query = context.Jobs.AsNoTracking().AsQueryable();

        if (criteria.Statuses is { Count: > 0 })
        {
            query = query.Where(job => criteria.Statuses.Contains(job.Status));
        }

        if (criteria.From is not null)
        {
            query = query.Where(job => job.ScheduledDate >= criteria.From);
        }

        if (criteria.To is not null)
        {
            query = query.Where(job => job.ScheduledDate <= criteria.To);
        }

        if (criteria.AssigneeId is not null)
        {
            query = query.Where(job => job.AssigneeId == criteria.AssigneeId);
        }

        if (!string.IsNullOrWhiteSpace(criteria.Text))
        {
            // A filter, not a sort. Ordering by ts_rank would force PostgreSQL
            // to compute and sort the whole matched set per page, which is the
            // cost profile keyset exists to remove (D-12).
            query = query.Where(job =>
                EF.Functions.ToTsVector("english", job.Title + " " + (job.Description ?? ""))
                    .Matches(EF.Functions.WebSearchToTsQuery("english", criteria.Text!)));
        }

        query = ApplyCursor(query, criteria);

        // coalesce, not the bare column: a NULL scheduled_date makes the row
        // comparison NULL rather than true and the row vanishes after page one
        // (architecture 6.4).
        query = query
            .OrderByDescending(job => job.ScheduledDate ?? DateOnly.MinValue)
            .ThenByDescending(job => job.Id);

        return await query
            .Take(criteria.Limit)
            .Select(job => new JobSearchResult(
                job.Id,
                job.Title,
                job.Status,
                job.ScheduledDate,
                job.AssigneeId,
                context.Assignees
                    .Where(a => a.Id == job.AssigneeId)
                    .Select(a => a.Name)
                    .FirstOrDefault(),
                job.Address.Street,
                job.Address.City,
                job.Address.State,
                job.Photos.Count))
            .ToListAsync(cancellationToken);
    }

    private IQueryable<Job> ApplyCursor(IQueryable<Job> query, JobSearchCriteria criteria)
    {
        if (!Guid.TryParse(criteria.Cursor, out var cursorId))
        {
            return query;
        }

        var anchor = context.Jobs.AsNoTracking()
            .Where(job => job.Id == cursorId)
            .Select(job => new { Date = job.ScheduledDate ?? DateOnly.MinValue, job.Id })
            .FirstOrDefault();

        if (anchor is null)
        {
            return query;
        }

        // The ordered pair, strictly beyond the cursor. Comparing the pair
        // rather than the date alone is what stops a row being skipped or
        // repeated when two jobs share a date.
        return query.Where(job =>
            (job.ScheduledDate ?? DateOnly.MinValue) < anchor.Date
            || ((job.ScheduledDate ?? DateOnly.MinValue) == anchor.Date && job.Id < anchor.Id));
    }
}
```

`DateOnly.MinValue` stands in for `'-infinity'`: Npgsql maps it to the earliest representable date, which sorts last under `DESC` exactly as the design intends. If the generated SQL turns out not to use the expression index, that is a finding for `database/indexes.sql` — verify with `EXPLAIN` in task 6 rather than assuming either way.

The EF translation of full-text search and of `coalesce` ordering is asserted by tests rather than assumed, but if either fails to translate the fallback must not be client-side evaluation — that would silently load the table and turn a keyset query into a full scan. `DateOnly.MinValue` stands in for `'-infinity'`, and the two are not the same value. It sorts last under `DESC` as intended, but the expression index in design B7 is declared over `coalesce(scheduled_date, '-infinity'::date)` — if Npgsql emits a different expression, the index will not be used and the plan captured in task 6 will show it. That is the check; the fix, if needed, is to align the index with what EF emits rather than the reverse.

**One thing left deliberately undone.** `PartyRepository` takes an `organizationId` it does not use, because the query filter already applies it. Removing it from `IPartyRepository` would make the domain interface silent about what scopes the operation; keeping it with a comment is the lesser cost, but it is the kind of thing that reads as an oversight to someone who has not read the filter.
